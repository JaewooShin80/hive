# Shared: 질문 방식 · `--auto` 모드

사용자에게 묻는 모든 `/hive:*` 스킬(spec, discover, plan, roadmap, security, uat, milestone)이 따르는 규칙.

## 1. 인자를 먼저 쓴다

스킬 인자(ARGUMENTS)에 설명·경로·선택이 이미 있으면 그것을 답으로 쓰고 같은 질문을 다시 하지 않는다.
예: `/hive:spec 보고자료로 우선순위를 정하는 앱` → "설명해 주세요" 단계를 건너뛴다.

## 2. 대화형 (기본): 묶어서 묻는다

- 서로 독립적인 질문은 `AskUserQuestion` 한 번에 최대 4개까지 묶는다. 각 질문의 첫 선택지는 추천안이며 라벨 끝에 `(Recommended)`를 붙인다.
- 앞 답에 따라 달라지는 질문만 다음 왕복으로 미룬다.
- 확인 단계(정리본 승인, Wave 구성 승인)는 한 번에 보여주고 한 번에 승인받는다.

## 3. `--auto` 모드

다음 중 하나면 `--auto`로 동작한다:
- 인자에 `--auto`가 있다.
- 사용자가 "묻지 말고", "추천안으로 진행", "알아서" 등으로 위임을 명시했다.

동작:
1. 질문하지 않는다. 각 질문에 대해 근거가 가장 강한 추천안을 고른다.
2. 고른 내용을 산출물의 **"가정 (auto)"** 섹션에 `- <질문> → <선택> (근거: …)` 형식으로 남긴다.
   - spec → REQUIREMENTS.md `## 미결정 사항` 아래 `### 가정 (auto)`
   - discover → ARCHITECTURE.md `## 가정 (auto)`
   - plan → PLAN.md 공통 규약 아래 `### 가정 (auto)`
   - security / uat → 리포트의 `가정 (auto)` 항목
3. 승인 단계는 자동 승인으로 기록하고 진행한다.
4. 끝에 가정 목록을 한 번에 출력해 사용자가 나중에 검토할 수 있게 한다.
5. 되돌리기 어렵거나 외부로 나가는 동작(원격 push, 배포, 데이터 삭제, git tag)은 `--auto`여도 하지 않고 안내만 한다.
